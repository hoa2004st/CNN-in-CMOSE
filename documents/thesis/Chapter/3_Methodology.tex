\label{sec:overview}

Two public datasets form the training data, while a self-collected set recorded on real webcams serves as an in-the-wild test set (Section~\ref{sec:data}). Every clip carries one of four ordinal engagement levels, from highly disengaged to highly engaged. Each clip is represented by per-frame OpenFace descriptors and a clip-level I3D embedding extracted from the raw video, then resampled to a common length and standardised with training-set statistics so that no target information leaks into preprocessing.

Two model paradigms are compared, contrasted in Figure~\ref{fig:overview_models}. The single-encoder baselines follow the standard approach, in which one encoder, an MLP, TCN, LSTM, or Transformer, consumes the full 709-dimensional OpenFace sequence, or an MLP consumes the pooled I3D vector, before a classifier produces the prediction (Section~\ref{sec:baselines}).

The proposed hybrid model replaces that single encoder with a split-and-encode design: the OpenFace descriptor is split into five meaning-based feature groups, each encoded independently by its own temporal encoder, the I3D vector is encoded by an MLP, and the resulting embeddings are concatenated and classified by a shared MLP while an auxiliary head supervises every stream (Section~\ref{sec:hybrid}). The loss functions, training regime, and 3$\times$3 cross-dataset protocol under which every model is trained and evaluated are established with the experiments that use them in Chapter~\ref{chap:results}.

\section{Data and Preprocessing}
\label{sec:data}

\subsection{Public datasets}

Two public datasets supply the labelled training data. DAiSEE~\cite{daisee} is a widely used engagement dataset of short webcam clips, recorded in the wild, each showing a single learner under uncontrolled conditions and annotated on a four-level ordinal engagement scale, which makes it realistic but noisy; it ships official Train, Validation, and Test partitions used here directly for training, early-stopping validation, and testing. CMOSE~\cite{cmose} is a more recent and larger dataset, likewise collected in the wild but annotated by experts and reporting strong inter-rater agreement, and it ships precomputed OpenFace and I3D features; it is divided into a labelled training split, an \texttt{unlabel} split repurposed as the validation set for early stopping and checkpoint selection, and a test split. Both label every clip on the same four ordinal levels used throughout the thesis, E0 (Highly\nobreakdash-Disengage), E1 (Disengage), E2 (Engage), and E3 (Highly\nobreakdash-Engage), so that CMOSE, with its greater scale and label quality, serves as the primary source and DAiSEE as an independent second source.
\input{Table/T3_1_dataset_stats}

Table~\ref{tab:T3_1_dataset_stats} shows that both public datasets are heavily imbalanced toward the upper-middle engagement levels, and imbalanced in different directions: CMOSE concentrates on the single Engage level, whereas DAiSEE divides more evenly between Engage and Highly\nobreakdash-Engage. The disengaged levels are rare in both, yet they are precisely the responses a monitoring system must catch. The same skew holds within each individual split, so it reflects the nature of the task rather than an artefact of how either dataset was partitioned. The self-collected private test set in the final row, though gathered independently, carries the same engaged-heavy imbalance, so the skew is a property of the engagement task and not of any single~collection.

\subsection{Private dataset}
\label{sec:private-collection}

The private set exists to measure deployment behaviour rather than in-dataset behaviour. No model is trained or selected on it, so it is a test-only set, and it is sampled from the webcam recordings a deployed model would actually face, so it probes a condition the public datasets leave untested. The reason this matters is geometric: the OpenFace gaze, head-pose, and landmark features are read from the camera's view of the face, so the same behaviour recorded from a different camera angle produces different feature values. Figure~\ref{fig:private-angles} shows private clips that differ along several axes: the camera's height and distance relative to the student's eye level, its position relative to the screen, its orientation, whether vertical or horizontal, and the background behind the learner, whether the real room, blurred, or a green screen. CMOSE and DAiSEE were recorded under far more uniform setups and so cannot exercise this variation, which makes a small, locally collected, hand-labelled set drawn from realistic online-class recordings the most direct way to check that a model stays fit once the camera geometry changes.

The set was built with the same feature pipeline as the public data. Webcam recordings of online-class sessions were sampled at several points and cut into fixed-length ten-second clips, each containing a single learner, and every clip was run through the OpenFace pipeline used for the public datasets, with clips that retained too few tracked frames discarded as unreliable. The accepted clips were then labelled through a purpose-built local interface, one engagement level per clip and by a single annotator, a reliance revisited as a limitation in Section~\ref{sec:summary}. Finally, the same OpenFace (709-d per frame) and I3D (1024-d per clip) extractors used for DAiSEE were applied, so the private features share the format of the precomputed CMOSE features and are distributionally comparable to the training data, and the 366 clips with complete, aligned OpenFace and I3D features form the final set. Its label prior differs again from both public datasets and, together with its independent recording conditions, makes it an in-the-wild measure of deployment behaviour that anchors Section~\ref{sec:private-result}.

\subsection{Preprocessing}

Each clip is represented by two feature streams. OpenFace~2.0~\cite{openface2} produces a 709-dimensional descriptor for every frame, and I3D~\cite{i3d} produces a single 1024-dimensional embedding pooled over the whole clip. CMOSE ships both precomputed; for DAiSEE and the private set they are extracted from the raw video with the same toolkits, so all three sources share one feature format. When an OpenFace frame reports more than one detected face the highest-confidence row is kept, and any non-numeric entry is set to zero. Because clips differ in length, each OpenFace sequence is resampled along time to a fixed number of frames by per-feature linear interpolation, 300 frames by default, reduced to 150 for the largest training runs to fit memory and to 75 in the multimodal variant, while the I3D stream, being a single vector per clip, needs no temporal resampling and is encoded by an MLP (Section~\ref{sec:hybrid}).

Every feature is then standardised by a per-feature $z$-score. The mean and standard deviation are fit on the training split alone, and the validation, test, and private sets are transformed with those training statistics, so no target-set information leaks into preprocessing. The OpenFace and I3D streams are standardised with separate~statistics.

\section{Baseline Models}
\label{sec:baselines}

Five single-encoder baselines establish the comparison points, and their architectures are shown in Figure~\ref{fig:baselines}. Each applies a single encoder to a feature stream and classifies the result.

The multilayer perceptron is the simplest of these encoders, and it serves as the first baseline for both feature streams. An MLP accepts only a fixed-length vector, so the per-frame OpenFace descriptor is flattened into one long vector before the network classifies it (\texttt{openface\_mlp}), and the I3D clip vector, already fixed in length, is passed to an MLP directly (\texttt{i3d\_mlp}). Flattening discards the order of the frames, so this baseline reads the clip as an unordered collection of measurements and marks the level that any time-aware model has to improve upon.

The OpenFace descriptor is a sequence, however, and its order carries information that flattening throws away. A clip is an ordered series of frames in the same way that a sentence is an ordered series of words: engagement shows in how the face moves from one frame to the next, not in any single frame read on its own. Three encoders built to read ordered sequences are therefore applied to the raw $T\times709$ OpenFace stream --- a temporal convolutional network (\texttt{openface\_tcn}), a recurrent network (\texttt{openface\_lstm}), and a Transformer (\texttt{openface\_transformer}). Each stands for one of the main families of sequence models, and each preserves the frame order that the MLP removes.

The I3D stream cannot be read in the same way. I3D already averages a whole clip into a single vector when the feature is extracted, so no per-frame sequence remains for a temporal encoder to consume. Its single fixed-length vector fits only an MLP, which is why the I3D stream supports one baseline while the OpenFace stream supports four.

\FloatBarrier
\section{Proposed Hybrid Model}
\label{sec:hybrid}

\subsection{Grouping the facial features by meaning}
\label{sec:groups}

The four OpenFace baselines share one weakness. A single encoder reads all 709 features at once, and so applies one inductive bias --- one built-in assumption about how a signal changes over time --- to every feature alike. No single assumption can fit them all, because the 709 features describe several distinct facial subsystems and those subsystems behave in very different ways: gaze and the eye landmarks shift in rapid, jittery micro-movements, head pose drifts slowly and smoothly, and the action units fire in short, sparse bursts. An encoder tuned to track quick eye movements is the wrong instrument for the slow drift of the head, so a single encoder over the whole descriptor suits a few of the features and misfits the rest.

Separating the features by the subsystem they describe removes this conflict. When a group holds only features that behave alike, it can be handed to the encoder whose assumption matches that behaviour, and no encoder is asked to serve incompatible dynamics at once. The 709 OpenFace features are accordingly split into five groups by meaning, matched from the column names in the fixed order used throughout the pipeline: gaze, eye landmarks, face landmarks, head pose, and action units. Table~\ref{tab:groups} lists the grouping, in which every one of the 709 columns belongs to exactly one group. This grouping by meaning is the central idea of the proposed model.

\subsection{Proposed model architecture}

The proposed hybrid model is shown in Figure~\ref{fig:hybrid}. It keeps the three encoder families used by the OpenFace baselines --- the TCN, the LSTM, and the Transformer --- but instead of applying one of them to the whole $T\times709$ descriptor, it gives each of the five feature groups its own encoder, combines the results, and supervises every stream with its own auxiliary head. Reusing the same three families is a deliberate choice: it ensures that any gain over the baselines can be traced to the grouping alone, and not to a more powerful kind of encoder.

Each group is read by its own \texttt{GroupEncoder}, one of the three interchangeable encoders drawn in Figure~\ref{fig:group_encoders}. Whichever encoder a group is assigned, its per-frame outputs are averaged over time and layer-normalised, so that every group leaves a 64-dimensional embedding of the same width regardless of how many raw features it began with. Fixing one common width matters because the groups differ greatly in size, from eight features for gaze to 340 for the face landmarks, and a shared width lets each contribute to the fused representation on an equal footing rather than in proportion to its raw dimensionality.

The five 64-dimensional embeddings are concatenated into a single 320-dimensional vector, which a two-layer classifier ($320\!\to\!128\!\to\!4$) maps to the four engagement logits. Each group also feeds a small auxiliary classifier of its own, and the training objective adds a fraction of the averaged auxiliary losses --- weighted at $0.2$ --- to the main loss (Section~\ref{sec:losses-method}). These auxiliary heads keep every stream discriminative on its own, so that no single group can be ignored while the others carry the prediction.

An optional sixth stream carries the I3D feature. Because I3D supplies a single pooled vector for the whole clip rather than a per-frame sequence, it is read by an MLP ($1024\!\to\!256\!\to\!128$) instead of a temporal encoder, and layer-normalised to a 128-dimensional embedding with its own auxiliary head. Enabling this stream widens the fused vector to 448 dimensions ($5\times64+128$); disabling it leaves the model on the five OpenFace groups alone, and both variants are carried forward for evaluation.

A single configuration of the model is therefore fixed by the encoder chosen for each of the five groups, written as an \texttt{arch\_key} of five tokens in group order --- for example \texttt{TCN\_T\_TCN\_LSTM\_T} (\texttt{T}~=~Transformer, \texttt{TCN}~=~TCN, \texttt{LSTM}~=~LSTM). With three encoders available to each group this gives $3^{5}=243$ possible configurations, and each can run with the I3D stream enabled or disabled.
