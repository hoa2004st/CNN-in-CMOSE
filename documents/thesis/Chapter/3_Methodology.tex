\FloatBarrier
\section{Overview}
\label{sec:overview}

The task is ordinal classification of a fixed-length clip into four engagement levels. Per-frame OpenFace descriptors and a clip-level I3D embedding are extracted, brought to a common length, and normalised. The two model paradigms then differ in how they consume these features (Figure~\ref{fig:overview_models}).

A single-encoder baseline follows the standard approach: a single encoder (MLP, TCN, LSTM, or Transformer) consumes the full 709-dimensional OpenFace sequence, or an MLP consumes the pooled I3D vector, and a classifier produces the prediction (Figure~\ref{fig:overview_baseline}). The proposed hybrid model replaces that single encoder with a split-and-encode design: the OpenFace descriptor is split into five feature groups, each encoded independently by its own temporal encoder, the I3D vector is encoded by an MLP, and the resulting embeddings are concatenated and classified by a shared MLP while an auxiliary head supervises every stream (Figure~\ref{fig:overview_hybrid}). Every model is trained and evaluated under the same 3$\times$3 cross-dataset protocol and three loss functions.

\section{Data and Preprocessing}
\label{sec:data}

\subsection{Datasets}

The thesis uses three training sources and three test sets, whose sizes and class balance are in Table~\ref{tab:T3_1_dataset_stats}.

\begin{enumerate}
  \item \textbf{CMOSE}~\cite{cmose}: 12{,}197 clips, split into \texttt{train} (8{,}783), \texttt{unlabel} (2{,}193) used here as the validation set for early stopping and checkpoint selection, and \texttt{test} (1{,}221).
  \item \textbf{DAiSEE}~\cite{daisee}: 8{,}571 clips, whose official \texttt{Train}/\texttt{Validation}/\texttt{Test} partitions map onto the same \texttt{train}/\texttt{unlabel}/\texttt{test} roles (5{,}358 / 1{,}429 / 1{,}784).
  \item \textbf{Combined}: the combination of CMOSE and DAiSEE (20{,}768 clips) with source-prefixed identifiers, merged split-wise into 14{,}141 / 3{,}622 / 3{,}005 train / validation / test clips.
  \item \textbf{Private (self-collected)}: 366 clips collected and hand-labelled for this thesis, used for testing only, never in training or model selection (Section~\ref{sec:private-collection}).
\end{enumerate}

All four sets share the four ordinal labels E0 (Highly\nobreakdash-Disengage), E1 (Disengage), E2 (Engage), and E3 (Highly\nobreakdash-Engage). Table~\ref{tab:T3_1_dataset_stats} and Figure~\ref{fig:dataset_class_distribution_overall} show that the three training datasets are heavily imbalanced toward the upper-middle classes, and imbalanced in different directions: CMOSE is dominated by E2 (69.4\%) with only 2.8\% E0, whereas DAiSEE is split between E2 (50.3\%) and E3 (43.8\%) with 0.7\% E0. The rare disengaged classes are precisely the ones a monitoring system must catch. The same imbalance holds within each split, so it is the nature of the problem, not an artefact of the partition.

This uneven imbalance shapes three choices the thesis returns to. It predicts difficulty in transferring between datasets, where a model fit to one label prior meets a different one at test time (Chapter~\ref{chap:results} and Appendix~\ref{chap:baseline}); it motivates the imbalance-aware losses of Section~\ref{sec:losses-method}; and, because predicting the majority class alone scores well on every dataset, it rules out accuracy as a selection criterion in favour of quadratic-weighted kappa (QWK), the single metric on which every best model is chosen, with macro-accuracy and macro-MAE kept as secondary balanced checks (Section~\ref{sec:eval}).

\subsection{The private evaluation set}
\label{sec:private-collection}

The private set measures deployment rather than in-dataset behaviour, and because no model is trained or selected on it, it is a test-only set. Although small, it is sampled in the wild, from the webcam recordings the model will face in deployment. It serves a purpose specific to engagement: the OpenFace gaze, head-pose, and landmark features are measured in the camera's image geometry, so a model validated only on the narrow range of setups in a public dataset offers no guarantee on the varied webcam angles of a real deployment. A small, locally collected, hand-labelled test set is the most direct way to check that a model is fit for its setting. It was built in five steps.

\begin{enumerate}
  \item \textbf{Source and segmentation.}
  Webcam recordings of online-class sessions were sampled at several points and cut into fixed-length 10-second clips, each containing a single learner.
  \item \textbf{Tracking-quality filtering.}
  Every clip was run through the same OpenFace pipeline as the public datasets; clips with too few tracked frames were rejected, since a descriptor from unreliable frames is meaningless.
  \item \textbf{Manual labelling.}
  The accepted clips were labelled through a purpose-built local interface, one engagement label per clip; reliance on a single annotator is a limitation revisited in Section~\ref{sec:limitations}.
  \item \textbf{Feature extraction.}
  Accepted clips were processed through the same OpenFace (709-d per frame) and I3D (1024-d per clip) pipeline used for DAiSEE, identical in format to the features CMOSE ships precomputed, so the private features are distributionally comparable to the training features.
  \item \textbf{Final set.}
  The 366 clips with complete, aligned OpenFace and I3D features form the private set. Its label prior differs again from both public datasets (58.2\% E2, 30.6\% E3, 8.5\% E1, 2.7\% E0), which, with its independent recording conditions, makes it an in-the-wild measure of deployment behaviour. It anchors Section~\ref{sec:private}.
\end{enumerate}

The four frames in Figure~\ref{fig:private-angles} illustrate why the private set is a stricter test of deployment behaviour than either public dataset. Each learner sets up their own device, so the camera sits at a different height and tilt relative to the face: roughly at eye level in Figure~\ref{fig:private-a}, mounted above the screen and looking down in Figure~\ref{fig:private-b}, below eye level and looking up in Figure~\ref{fig:private-c}, and at a steep upward tilt from a portrait-oriented phone in Figure~\ref{fig:private-d}. Framing, background, lighting, and distance to the lens vary alongside the angle. Because the OpenFace gaze, head-pose, and landmark descriptors are measured in the camera's image geometry, this spread of viewpoints shifts the very features the models consume, in ways that the more uniform studio-style setups of CMOSE and DAiSEE do not exercise. The private set therefore probes whether a model trained on constrained recordings still generalises to the varied webcam geometry of a real online class.

\subsection{Features and preprocessing}

Each clip is represented by per-frame OpenFace~2.0 descriptors (709-d)~\cite{openface2} and a clip-level I3D embedding (1024-d)~\cite{i3d}. CMOSE ships these features precomputed; for DAiSEE and the private set both are extracted from the raw video with the same toolkits, so all three sources share one feature format. When an OpenFace frame contains more than one detected face, the highest-confidence row is kept, and non-numeric entries are set to zero.

OpenFace clips vary in length, so each is resampled along time to a fixed number of frames by per-feature linear interpolation. The OpenFace sequence length is 300 frames for the single-dataset runs, reduced to 150 for the larger Combined runs to fit memory, and to 75 frames in the multimodal variant. The I3D feature is a single 1024-dimensional vector per clip, not a sequence, encoded by an MLP (Section~\ref{sec:hybrid}).

Every feature is standardised by a per-feature $z$-score whose mean and standard deviation are fit on the training split only; the validation, test, and private sets are transformed with those training statistics, so no target-set information leaks into preprocessing. OpenFace and I3D are standardised with separate statistics.

\section{Baseline Models}
\label{sec:baselines}

Five single-encoder baselines provide the comparison points and form the allow-list \texttt{MODEL\_ORDER} used by the analysis. Each applies one encoder to the full feature sequence before a classifier.
\begin{enumerate}
  \item \texttt{openface\_mlp}: flattens the OpenFace sequence and classifies it with an MLP ($\to$256$\to$128$\to$4, dropout 0.3).
  \item \texttt{openface\_tcn}: a TCN over the 709-d sequence (residual dilated blocks of widths $256,128,128$; kernel 3; dilations $1,2,4$), adaptive average-pooling, then a $128\!\to\!128\!\to\!4$ classifier.
  \item \texttt{openface\_lstm}: a two-layer LSTM (hidden width 256) whose final hidden state feeds a $256\!\to\!128\!\to\!4$ classifier.
  \item \texttt{openface\_transformer}: a linear projection to 128 dimensions, a sinusoidal positional encoding, and two Transformer encoder layers (4 heads, feed-forward width 256), mean-pooled and classified.
  \item \texttt{i3d\_mlp}: classifies the single 1024-d I3D clip vector with an MLP ($1024\!\to\!256\!\to\!128\!\to\!4$, dropout 0.3).
\end{enumerate}
A sixth model, \texttt{openface\_tcn\_i3d\_fusion} (a shared-fusion TCN over both modalities), exists in the codebase but is excluded from the assessment so the comparison isolates the feature-group hypothesis rather than modality fusion.

The five baseline architectures are shown in Figure~\ref{fig:baselines}. The four OpenFace baselines (a--d) encode the full $T\times709$ sequence with a single encoder, while \texttt{i3d\_mlp} (e) classifies the pooled 1024-d I3D clip vector. Forcing one encoder, and therefore one temporal bias, onto all 709 mixed features is the design decision the proposed model revisits in Sections~\ref{sec:groups} and~\ref{sec:hybrid}.

\section{Grouping the Facial Features by Meaning}
\label{sec:groups}

The 709 OpenFace features are partitioned into five meaningful groups by matching the column names, in the fixed order used everywhere in the pipeline (gaze, eye, face, head, action units). Table~\ref{tab:groups} summarises the partition; every one of the 709 columns belongs to exactly one group.

\begin{table}[ht]
\centering
\caption{Grouping of the 709-dimensional OpenFace descriptor into five feature groups by meaning.}
\label{tab:groups}
\begin{tabular}{llr}
\toprule
Group & Content & Dim \\
\midrule
Gaze          & gaze direction vectors and angles            & 8   \\
Eye landmarks & 2-D/3-D eye-region landmark coordinates        & 280 \\
Face landmarks& 2-D/3-D facial landmark coordinates            & 340 \\
Head pose     & head translation and rotation parameters      & 46  \\
Action units  & facial action-unit presence and intensity     & 35  \\
\midrule
\textbf{Total} & & \textbf{709} \\
\bottomrule
\end{tabular}
\end{table}

This decomposition is the inductive prior of the method. The five subsystems have different dynamics, so each can be matched to an encoder whose temporal bias suits it: gaze and eye landmarks show rapid, noisy micro-saccades; head pose drifts slowly and smoothly; action units fire in brief, sparse bursts. Encoding all 709 features together, as the single-encoder baselines of Section~\ref{sec:baselines} do, forces a single bias on all of them at once.

\section{Proposed Hybrid Model}
\label{sec:hybrid}

The proposed hybrid model, shown in Figure~\ref{fig:hybrid}, encodes each stream independently, fuses the resulting embeddings, and supervises every stream with its own auxiliary head. It is built from the same three encoder families as the OpenFace baselines of Section~\ref{sec:baselines} (TCN, Transformer, LSTM), but where a baseline applies one encoder to the full $T\times709$ sequence, the proposed model assigns an independently chosen encoder to each of the five feature groups of Section~\ref{sec:groups}, so any difference in performance is attributable to the decomposition rather than to a different kind of encoder.

Each group is encoded by a \texttt{GroupEncoder}, one of three interchangeable temporal encoders (Figure~\ref{fig:group_encoders}), followed by temporal mean-pooling and a layer normalisation, producing a 64-dimensional embedding:
\begin{enumerate}
  \item a TCN: two residual blocks of dilated causal 1-D convolutions (channel widths $64,64$; kernel size 3; dropout 0.2);
  \item a Transformer encoder: a linear projection to 64 dimensions, a sinusoidal positional encoding, and two encoder layers (4 heads, feed-forward width 128, GELU, dropout 0.2);
  \item an LSTM: a two-layer recurrent encoder of hidden width 64 (dropout 0.2).
\end{enumerate}

\caption{The three interchangeable per-group encoders.}
\label{fig:group_encoders}
\end{figure}

The five 64-d group embeddings are concatenated into a 320-d vector and passed through a two-layer MLP classifier ($320\!\to\!128\!\to\!4$, ReLU, dropout 0.3) that produces the main logits. Each group additionally feeds an auxiliary classification head ($\mathrm{dropout}\to\mathrm{Linear}(64\!\to\!4)$). The total loss is the main-head loss plus $\texttt{aux\_weight}=0.2$ times the mean of the per-group losses (Section~\ref{sec:losses-method}); the auxiliary supervision makes each stream individually discriminative.

The I3D-stream-enabled variant adds a sixth stream: the single 1024-d I3D clip vector is encoded by an MLP ($1024\!\to\!256\!\to\!128$, ReLU, dropout 0.3) and layer-normalised to a 128-d embedding with its own auxiliary head, so the fusion MLP takes a 448-d input ($5\times64 + 128$). The I3D stream uses an MLP rather than a temporal encoder because the provided I3D feature is a single pooled vector, not a sequence.

A configuration of the proposed hybrid model is fully specified by the encoder chosen for each of the five groups, written as an \texttt{arch\_key} of five tokens in group order, for example \texttt{TCN\_T\_TCN\_LSTM\_T} (\texttt{T}~=~Transformer, \texttt{TCN}~=~TCN, \texttt{LSTM}~=~LSTM). With three choices per group there are $3^{5}=243$ configurations, each evaluated with the I3D stream enabled and disabled (Section~\ref{sec:ablation}).
